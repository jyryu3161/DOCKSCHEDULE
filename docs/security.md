# 보안 정책

## 보호 대상

- 학생의 업로드(PDB, library), 전처리 단백질, docking 결과(pose, 점수). 학생 간에는 서로 완전히 격리되고 관리자만 전체를 본다.
- 계정 정보(ID, 이름, 학번, 비밀번호 hash), 로그인 세션.
- 배포 비밀: `.env`의 관리자 초기 비밀번호, DB 비밀번호. 백업 파일.
- 서버 자원(CPU, 디스크). 승인되지 않은 사용과 한 학생의 독점을 막는다.

## 네트워크 경계

- 서비스는 학내망 전용이다. web(nginx)이 `ALLOWED_NETWORKS`에 적힌 CIDR(그리고 호스트 로컬 접속을 위한 Docker bridge gateway)만 허용하고 나머지는 `deny all`(403)이다. `0.0.0.0/0`을 허용 목록에 넣지 않는다.
- nginx는 `X-Forwarded-For`를 클라이언트가 보낸 값이 아니라 실제 source 주소(`$remote_addr`)로 덮어쓴다. 위조한 `X-Forwarded-For`로 허용 목록을 우회할 수 없다.
- api는 `--forwarded-allow-ips "*"`로 프록시 헤더를 신뢰한다. 이 신뢰는 api 포트가 호스트에 공개되지 않고 nginx만 접근한다는 전제 위에 있다. api(8000)나 DB·Redis 포트를 호스트에 게시하면 안 된다.
- HTTPS는 사용하지 않는다(학내 HTTP). 이때 `COOKIE_SECURE=false`이며, HTTPS reverse proxy를 앞에 두면 `COOKIE_SECURE=true`로 바꾼다.

## 인증 흐름

1. 가입(`POST /api/auth/register`): ID(3~80자, 영문·숫자·`_.-`), 이름, 학번, 비밀번호(8~128자). ID `admin`(대소문자 무관)은 거절(409), 중복 ID는 409. 가입 직후 상태는 `pending`. IP당 분당 60회 제한(429).
2. 로그인(`POST /api/auth/login`): IP+ID 조합당 분당 15회 제한(429). ID가 없거나 비밀번호가 틀리면 같은 메시지로 401(어느 쪽이 틀렸는지 알려주지 않는다). 비밀번호가 맞아도 `rejected`/`suspended`면 403.
3. 성공하면 서버가 무작위 토큰(48바이트)을 만들어 SHA-256 해시만 DB에 저장하고, 원문은 쿠키 `ds_session`(HttpOnly, SameSite=Strict, `COOKIE_SECURE` 설정에 따라 Secure, 유효시간 `session_hours`=12시간)으로만 전달한다.
4. 모든 보호된 요청은 쿠키 → 세션 조회 → 사용자 조회를 거친다. 세션이 없거나 만료되면 401, 사용자가 `rejected`/`suspended`면 403, `pending`이면 `approved`가 필요한 기능에서 403.
5. 로그아웃은 해당 세션을 삭제한다. 비밀번호를 바꾸면 그 사용자의 모든 세션이 삭제된다(현재 세션 포함, 다시 로그인).
6. 관리자 비밀번호 초기화는 임시 비밀번호를 생성해 응답으로 한 번 전달하고, 대상의 모든 세션을 삭제한다.

비밀번호는 Argon2로 저장한다. 첫 실행에 `ADMIN_PASSWORD`로 `admin` 계정을 만들며(없으면 시작 실패), 이후 변경은 DB의 hash가 기준이고 재시작이 설치 당시 비밀번호로 되돌리지 않는다.

로그인·가입 횟수 제한은 api 프로세스 메모리에 있다. api를 여러 프로세스로 늘리면 제한이 프로세스별로 따로 적용된다.

## 권한 모델

| 주체 | 허용 | 명시적으로 허용하지 않음 |
| --- | --- | --- |
| 비로그인 | 가입, 로그인, `/api/health` | 그 외 모든 API |
| `pending` 학생 | 로그인, 본인 정보 조회, 로그아웃, 비밀번호 변경 | 업로드, 설정 조회, 작업·결과 접근 (403) |
| `approved` 학생 | 본인 소유 업로드·receptor·작업·화합물 결과·분석의 조회/생성/취소/재시도/삭제(screening), 설정 조회 | 다른 학생의 자료(존재 여부를 숨기려고 403이 아니라 404), 관리자 API |
| `rejected`/`suspended` | 없음 | 로그인 자체가 막힘, 기존 세션은 삭제됨 |
| `admin` | 모든 학생의 자료 조회·취소·재시도·삭제, 계정 승인/거절/정지, CPU 개별 설정, 비밀번호 초기화, 전체 설정, 저장 공간 현황 | 관리자 계정의 정지·거절 (400) |

- 소유권 검사는 모든 자료 API(업로드, receptor, 작업, 화합물 pose, 점수·ZIP·CSV, 상호작용 인덱스·후보·pose 분석)에 같은 방식(`owned`)으로 적용한다. 새 엔드포인트도 반드시 같은 검사를 거쳐야 한다.
- 관리자가 학생 작업에 대해 분석을 요청하면 용량 한도는 작업 소유자 기준으로 검사한다.
- 상태 변경 요청(POST/PATCH/PUT/DELETE)은 헤더 `X-DS-Request: 1`이 있어야 하고, `Origin`이 있으면 요청 `Host`와 같아야 한다(CSRF 방어). 아니면 403.
- 응답에는 `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`를 붙인다.

## 감사 대상

다음 사건은 반드시 `audit` 테이블에 행위자·대상·세부 정보와 함께 기록한다.

- 계정 변경(`update_user`: 상태·CPU 개별 설정), 비밀번호 초기화(`reset_password`)
- 설정 변경(`settings`, 전체 값 포함)
- 작업 제출(`submit`), 취소(`cancel`), 재시도(`retry`), 삭제(`delete_job`)
- 라이브러리 상호작용 분석 요청(`analyze_library`)
- 보존 기간에 의한 자동 삭제(`retention_delete`, 행위자 없음)

로그인, 가입, 파일 업로드, 전처리 요청, 조회·다운로드는 기록하지 않는다(의도한 범위다). 관리자 계정은 `bootstrap`이 만드는 `admin` 하나뿐이고 역할을 올리는 API가 없으므로 모든 관리 행위의 행위자는 이 공유 계정이다. 조교·그룹·학생 간 공유 같은 중간 권한은 없다.

## 자격 증명과 민감 정보

- 비밀번호 원문은 저장하지 않으며 로그·감사 기록·응답에 담지 않는다(초기화 시 임시 비밀번호가 응답에 한 번 나오는 경우만 예외).
- `.env`는 소유자만 읽도록(권한 600) 두고 저장소에 커밋하지 않는다. 설치 스크립트는 비밀번호를 출력하지 않고 개행·작은따옴표가 든 비밀번호를 거절한다.
- 백업(DB 덤프, storage, 배포 `.env` 사본)은 소유자만 접근하도록(디렉터리 700, 파일 600) 둔다.
- 학번은 개인정보다. 관리자 화면과 사용자 정보 API에만 나타나야 하며 결과 파일·내보내기에 넣지 않는다.
- 학생이 입력한 SMILES·CID는 CSV 내보내기에서 수식 접두 문자를 `'`로 무력화한다. 업로드 파일명은 DB 표시용으로만 쓰고 파일 경로·명령에 사용하지 않는다(저장 경로는 서버가 만든 ID).
- 파일 접근은 `storage.inside()`로 저장소 루트 아래인지 확인한다.

## 업로드 제한

업로드 크기는 `max_upload_mb`(기본 100)를 넘으면 413, nginx `client_max_body_size`도 100m이다. 둘은 함께 바꿔야 한다. 저장 공간 한도 위반은 422다.
