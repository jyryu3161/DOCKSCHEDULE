# 0001. docking 엔진으로 QuickVina 2.1 사용

## 맥락
학생이 결합 위치(grid 중심·박스)를 직접 지정하는 수업용 CPU docking이다. 학생 약 40명이 각각 최대 100,000개 화합물을 제출하므로 화합물당 계산 시간이 짧아야 하고, 엔진 바이너리의 신뢰성이 결과 재현성의 기반이다.

## 결정
QuickVina 2.1을 쓴다. 공식 저장소의 고정 커밋(`f4bb3b1…`)에서 받은 x86_64 바이너리를 SHA256으로 검증하고(설치 시, 작업 시작 시) 일치하지 않으면 실행하지 않는다. 화합물당 `--num_modes 1`로 conformer별 최상 pose를 얻고 여러 conformer 중 가장 낮은 affinity를 고른다.

## 대안
- 결합 위치를 모르는 상태에서 전역 탐색하는 방식: 학생이 위치를 지정하는 용도이므로 필요하지 않다. 공식 프로젝트도 위치를 알 때 QuickVina 2를 권장한다.
- 소스 빌드: 빌드 환경 차이로 바이너리가 달라질 수 있어 고정된 공식 바이너리와 체크섬 검증을 택했다.

## 결과
- x86_64 Linux만 지원한다(고정 바이너리 때문).
- 엔진을 바꾸거나 업그레이드하려면 체크섬·커밋·라이선스 문서·준비 도구(Meeko, Open Babel)의 원자형 호환성을 함께 재검증해야 한다.
- 점수는 docking score(교육용)이며 실험 친화도로 해석할 수 없다. 이후 계획된 GNINA 재점수화는 이 결정을 대체하지 않고 QuickVina pose 위에 추가된다.
