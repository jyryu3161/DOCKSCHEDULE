# 0004. 학생당 동시 작업 1개와 학생별 고정·비중복 CPU

## 맥락
공용 서버(논리 CPU 64개)에서 학생 약 40명의 장시간 계산을 돌린다. 처음 요구는 학생 간 완전 순차 실행이었고, 관리자가 조절 가능한 병렬 실행으로 확장되었다. 한 학생이 서버를 독점하거나 라이브러리가 CPU를 임의로 더 쓰면 다른 학생과 웹 서비스가 느려진다.

## 결정
한 학생은 동시에 작업 하나만 실행한다. 실행되는 작업마다 서로 겹치지 않는 CPU 집합을 예약하고 `sched_setaffinity`와 스레드 수 환경변수, QuickVina `--cpu`로 그 안에 가둔다. 관리자는 전체 CPU 한도(`cpu_budget`), 동시 학생 수, 학생당 CPU 기본값과 개별 설정을 조절한다. 동시 학생 수를 1로 두면 완전 순차 모드가 된다.

## 대안
- 공유 풀에서 CPU를 자유롭게 사용: 한 학생의 대형 작업이 다른 학생을 굶기고 처리 시간을 예측할 수 없다.
- 학생 한 명의 작업을 여러 개 동시에 실행: 학생별 CPU 몫이 모호해지고 자원 반환 추적이 복잡해진다.

## 결과
- 한도를 낮춰도 실행 중인 작업의 예약은 종료 때까지 유지된다(즉시 줄이려면 취소).
- 큰 CPU 요구 작업이 작은 작업에 밀릴 수 있다(스케줄러는 엄격한 FIFO가 아니다).
- 같은 학생의 전처리·docking·상호작용 분석이 서로 순서대로만 실행된다.
- CPU를 늘려도 처리량이 비례해 늘지 않는다(측정: 1·2·4·8 CPU에서 화합물당 평균 16.5·8.4·5.1·2.7초).
