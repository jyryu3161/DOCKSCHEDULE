# 0006. 상호작용은 잔기·타입 요약만 저장하고 원자별 표는 조회 때 계산

## 맥락
library 전체(최대 100,000개)에서 "특정 잔기와 특정 종류로 상호작용하는 화합물"을 빠르게 찾아야 한다. 반면 원자별 전체 표(거리·각도·원자 목록)는 pose 하나를 볼 때만 필요하다.

## 결정
라이브러리 분석은 화합물별 성공/실패와, (잔기 키, 타입)별 접촉 수·최소 거리만 DB(`interaction_hits`)에 저장한다. 원자별 전체 표는 저장하지 않고 pose를 열 때 api가 하위 프로세스로 계산한다(CPU 1개·45초·한 번에 하나, 최근 32개 캐시).

## 대안
- 원자별 전체 결과를 모두 영속화: 용량과 migration 부담이 크고 ProLIF 버전·기준이 바뀌면 일괄 무효화해야 한다.
- 후보 검색 때마다 즉석 계산: 100,000개를 요청 시간 안에 분석할 수 없다.

## 결과
- 후보 검색은 인덱스 조회(`interaction_lookup`)로 빠르다.
- 원자별 표는 같은 pose라도 캐시가 없으면 매번 계산한다(약 1.65초 관측, 구조에 따라 다름).
- 접촉 0개인 성공과 분석 실패를 구분해야 하므로 화합물별 분석 상태 행을 둔다.
- docking을 재시도해 다시 계산되는 화합물은 이전 분석·접촉 기록을 지워야 한다.
