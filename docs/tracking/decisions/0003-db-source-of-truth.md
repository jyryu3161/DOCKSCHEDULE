# 0003. 상태의 기준은 PostgreSQL, Redis는 전달용

## 맥락
작업은 며칠 단위로 오래 걸리고 서버·컨테이너가 재시작될 수 있다. 재시작 뒤 어디까지 끝났는지와 어떤 CPU가 누구에게 예약됐는지를 틀리지 않고 복구해야 한다.

## 결정
작업·화합물 진행·CPU 예약·설정은 PostgreSQL이 유일한 기준이다. Redis(RQ)는 runner에게 작업 번호를 넘기는 큐와 연결 확인에만 쓴다. Redis에 연결할 수 없으면 새 작업 배정을 멈추고 오류를 기록하며(`scheduler_error`), 다른 executor로 우회 실행하지 않는다. 화합물은 하나 끝날 때마다 DB에 체크포인트한다.

## 대안
- Redis(RQ)를 상태의 기준으로 삼기: 큐가 유실되면 진행 상태를 복구할 수 없다.
- Redis 장애 시 로컬 executor로 폴백: CPU 예약과 어긋난 프로세스가 생겨 학생 간 CPU 격리가 깨진다.

## 결과
- scheduler는 1초 간격으로 DB를 폴링한다.
- Redis가 죽은 동안 대기 작업은 시작되지 않고 이미 실행 중인 작업만 계속된다.
- 복구는 DB 상태와 실제 프로세스(PID·생성 시각·`run_id`)를 대조해서만 한다. 폴백 경로를 추가하려면 이 결정을 먼저 바꾸어야 한다.
